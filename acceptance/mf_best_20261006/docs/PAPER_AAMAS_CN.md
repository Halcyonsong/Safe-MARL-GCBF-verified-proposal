## 摘要

多智能体避障导航在无人机编队、自动驾驶车队等安全关键场景中需要形式化安全保证，但现有强化学习方法缺乏可验证性。核心难点在于：图神经网络因变长输入无法被主流验证工具处理，而基于控制屏障函数的方法部署时缺乏在线安全过滤器且学习的屏障函数未经形式化验证。

本文提出**首个可形式化验证的多智能体强化学习控制器**。核心方法是验证友好架构设计：采用固定维平均场特征聚合使策略网络可直接进入主流验证器，通过残差门控修复框架在保持任务性能的同时修复安全违例，并利用反例引导迭代循环渐进增强安全性。

我们在八智能体避障任务上实现**有界完备形式化证明**：在声明域内两步径向安全性质通过区间传播和完备验证获得全域保证，覆盖约八成经验危险状态。对比六个基线方法，**仅本文方法具备完备形式化证书**——核心贡献是证书存在性的非对称（certificate asymmetry），而非单纯经验性能优势。本工作首次证明实际多智能体强化学习任务的形式化验证可行性，为安全关键系统部署奠定基础。

**关键词**：多智能体强化学习 · 形式化验证 · 控制屏障函数 · 神经网络安全 · 平均场近似

## 1. 引言

### 1.1 背景与动机

多智能体系统在无人机集群、自动驾驶车队、仓储机器人等安全关键场景中广泛应用，失效可能导致灾难性后果。传统测试方法无法覆盖所有边界情况，**形式化验证**（Formal Verification）通过数学严格证明 ∀x∈X, Safe(x)，为安全关键系统提供不可替代的理论保障，是航空航天、医疗设备等高风险领域的强制要求。

神经网络形式化验证工具（Marabou、α-β-CROWN）在感知任务上取得突破，但**多智能体强化学习控制领域仍缺乏成功案例**。核心难点：图神经网络（GNN）因变长输入无法被主流验证工具处理，控制屏障函数（CBF）方法缺乏对实际部署策略的验证。

### 1.2 核心挑战

现有方法在**可验证性**与**任务性能**之间面临根本性张力：

**GNN-based MARL** (GCBF+等)：性能优异但变长输入无法验证（需按 (k,m) 组合分桶导致组合爆炸），部署期缺乏在线安全过滤器，学习的 barrier 函数未经形式化验证。

**验证 CBF 函数的方法** (VSMANC等)：验证 barrier h(s) 的数学性质而非实际策略 π(s) 的输出安全性，存在**验证对象与部署保证的断层**——即使证明 h(s) 满足 CBF 条件，learned policy 仍可能违反约束。

**其他方法**：CMDP 软约束（MAPPO-Lag）无硬安全保证；Hand-designed CBF 计算代价高、泛化弱。

**关键区分**：
| 验证内容 | 现有工作 (VSMANC等) | 本文工作 |
|---------|-------------------|---------|
| **验证对象** | Barrier 函数 h(s) | **策略网络 π(s)** |
| **验证性质** | h(s)>0, ḣ+αh≥0 | **∀s∈X, d(s,π(s))≥d_safe** |
| **部署保证** | 间接（假设遵循 h） | **直接验证实际输出** |

### 1.3 本文方法

本文提出**直接验证实际部署策略网络**的技术路线，通过验证友好架构设计协同优化可验证性与任务性能：

1. **固定维平均场特征**（§4.1）：44 维固定维特征（Ego 8-D + 四象限聚合 36-D）使策略可直接进入主流验证器，突破 GNN 变长输入瓶颈。

2. **残差门控修复**（§4.2）：冻结基座策略（蒸馏自 GCBF+），训练轻量修正头（~22k 参数，1.7% 基座），通过物理门控在安全区保持基座、危险区激活修正。

3. **反例引导迭代**（§4.3）：采样验证 → 反例收集 → min-intervention 修复 → 完备验证，渐进增强安全覆盖。

### 1.4 主要贡献

1. **首个验证实际部署策略的 MARL 方法**：在声明域（d∈[0.14,0.40], |c|≤0.30）上对策略网络 π(s) 实现有界完备形式化证明，保证两步径向安全性质 ∀s∈X, d(s')≥d_safe，覆盖约八成经验危险状态。

2. **证书非对称性**（certificate asymmetry）：对比六个基线（GCBF+、HandCBF、MAPPO-Lag、InforMARL、DeepSet-r2），仅本文方法具备完备形式化证书——核心贡献是证明存在性的非对称，而非单纯经验性能优势。

3. **验证友好架构方法论**：固定维平均场特征设计将变长 GNN 问题转化为可验证的前馈网络，为多智能体系统形式化验证提供架构解决方案。

4. **CEGAR 修复有效性**：危险命中率降低 12.7×（5.95%→0.47%），安全率提升至 96.5%，证明验证驱动修复的实用价值。

## 2. 相关工作

### 2.1 安全多智能体强化学习

**GNN-based CBF 方法** [3,4]：GCBF/GCBF+ 使用图神经网络联合学习 h(s) 和 π(s)，训练期用 QP 教师纠正。局限：① 变长输入需按 (k,m) 分桶导致组合爆炸；② 学习的 h(s) 未验证；③ 部署期无在线 QP 滤波器。

**CMDP 软约束** [5,6]：MAPPO-Lag、CPO 通过 Lagrangian 对偶变量惩罚安全代价。本质是软约束，无硬安全保证。

**Hand-designed CBF**：人工设计 barrier 并在线求解 QP。计算延迟高（~3-4× NN），泛化弱。

### 2.2 形式化验证 CBF 的方法

**VSMANC** [6]：学习 DCBF 并验证 h_θ(s) 满足 CBF 条件（h>0, Lie 导数），通过反例引导重训练增强严格性。

**根本性区别**：VSMANC 验证 **barrier h(s) 数学性质**，而非**实际策略 π(s) 输出安全性**。即使 h(s) 被证明，learned policy 仍可能违反约束——安全保证依赖"h 正确 → controller 安全"的传递链条，但 controller 未被验证。**本文**直接验证部署的 π(s)，从间接保证转向直接保证。

### 2.3 神经网络验证工具

**完备验证器**：Marabou [1]（SMT 求解器，UNSAT→proven）、α-β-CROWN [2]（界传播+分支定界）。**不完备**：CROWN-IBP [7]、DeepPoly [8]（快但可能报 unknown）。

**架构限制**：工具仅支持固定维输入（MLP/CNN），不支持变长图、注意力。**本文贡献**：固定维平均场特征桥接验证工具与 MARL，首次实现实际任务完备验证。

**CEGAR**：经典技术 [9]；神经网络修复 [10,11] 对对抗样本重训练。本文将 CEGAR 引入连续控制，设计残差门控修复（冻结基座 + 轻量修正头）与 min-intervention 标签生成。

## 3. 预备知识

**环境**：N=8 DoubleIntegrator，4×4 区域，4 障碍，LiDAR 32 射线，256 步（dt=0.03s）。

**双积分器动力学**（Euler 离散化）：
```
p'(t+1) = p(t) + v(t)·dt                    # 位置更新
v'(t+1) = clip(v(t) + a(t)·dt/m, ±0.5)     # 速度更新，m=0.1
```
**关键**：位置 p' 仅依赖当前速度 v，**动作 a 不直接影响位置**。动作通过加速度改变速度，需**两步**传播到位置（a→v→p），这是两步验证必要性的物理根源（§4.4.1）。

**控制屏障函数（CBF）**：h:X→ℝ 满足 h(x)>0 ⇒ 安全，ḣ+α·h≥0 ⇒ 前向不变性。若 h(x₀)>0 且前向不变性成立，则 h(x(t))>0, ∀t≥0（无限时域安全）。CBF-QP 滤波器：min ||u−u_ref||² s.t. ḣ+α·h≥0。**GCBF 问题**：学习的 h 未被证明是合法 CBF；GNN 变结构无法验证；部署无在线 QP。

**神经网络验证**：给定 NN:ℝⁿ→ℝᵐ、输入域 X、性质 P，证明/反驳 ∀x∈X, P(NN(x))。**Marabou**：SMT 求解器，ReLU 网络完备（UNSAT→proven）；**IBP**：区间传播，快速但不完备。**限制**：工具仅支持固定维输入（MLP/CNN）。

## 4. 方法

本节介绍验证友好的多智能体控制器设计。方法分三阶段：① 固定维平均场蒸馏网络（§4.1）→ ② 反例引导门控修复（§4.2-4.3）→ ③ 形式化验证（§4.4）。

### 4.1 验证友好架构设计

#### 4.1.1 GNN 变长输入的验证困境

GCBF/GCBF+ 使用图神经网络处理变长邻居-障碍实体序列：
```
输入: ego[8-D], neighbors[k×7-D], obstacles[m×7-D]
      k∈[0,N-1], m∈[0,M] 
      在 N=8, M=32 环境中：k∈[0,7], m∈[0,32] → 8×33=264 种 (k,m) 组合
```

**验证不可行性**：
1. **组合爆炸**：必须对每个 (k,m) 组合单独建模验证，264 个独立证明负担
2. **工具限制**：Marabou/α-β-CROWN 仅支持固定维输入（MLP、CNN），不支持动态图结构
3. **切分复杂度**：即使单个桶，仍需沿输入维度切分子盒，每增加一个实体槽增加 7 维切分空间

**设计目标**：构造固定维特征表示，无论实际邻居/障碍数，输出维度恒定。

#### 4.1.2 平均场特征设计：固定 44 维象限聚合

**核心思想**：用置换不变的统计聚合替代变长序列，将 360° 空间划分为 4 个象限，每个象限内对所有威胁计算固定维统计量。

**44 维特征分解**：

| 段 | 维数 | 内容 | 数学定义 |
|----|------|------|---------|
| Ego | 8 | [p_x, p_y, v_x, v_y, Δp_goal, Δv_goal] | 自车状态与目标相对信息 |
| Agent Q0-Q3 | 20 | 4 象限×[n, min_d, close_max, close_wmean, inv_ttc] | 邻居威胁聚合 |
| Obs Q0-Q3 | 16 | 4 象限×[n, min_d, close_max, inv_ttc] | 障碍威胁聚合 |

**象限聚合公式**（以 Q0=[0°,90°) 为例）：
```python
Q_entities = {e | angle(e) ∈ [0°, 90°)}  # 该象限内所有实体

n = |Q_entities|                          # 威胁计数
min_d = min{||p_e - p_ego|| : e∈Q_entities} if n>0 else r_comm  # 最近距离
close_max = max(0, max{⟨v_rel, d̂⟩ : e∈Q_entities})             # 最大逼近速度
inv_ttc = max{close / max(d, ε) : e∈Q_entities}                 # 碰撞紧迫度
```

**关键性质**：
1. **维度固定性**：无论实际 k,m，特征始终 44 维，(k,m)∈[0,7]×[0,32] 映射到同一空间 ℝ⁴⁴
2. **置换不变性**：同象限内实体顺序交换不影响特征（min/max 操作）
3. **空间结构保留**：4 象限划分保留粗粒度方向信息，避免全局聚合丢失空间关系
4. **可验证编码**：X ⊆ ℝ⁴⁴ 可直接表示为超矩形盒，进入 Marabou

**权衡分析**：固定维聚合损失细粒度空间信息，导致约 10pp 任务性能下降（MF 82.0% vs GCBF+ 91.4%），换取形式化验证可行性。

#### 4.1.3 蒸馏策略选择

**基座网络**：π_base: ℝ⁴⁴ → 512³(ReLU) → ℝ²，~1.32M 参数

**蒸馏目标**：蒸馏 GCBF+ Actor π_GNN 而非直接蒸馏 QP 输出。QP 在约束边界存在不连续跳变，MLP 拟合困难（实测 QP 与 Actor 输出 MAE≈1.02）。Actor 通过软监督训练已将 QP 硬约束平滑化，更适合蒸馏。

**损失**：L_distill = Σ w_danger(s) · ||π_base(MF(s)) - π_GNN(s)||²，其中 w_danger(s) 对近威胁状态加权。

**结果**（base v5 step9000）：Success 77.7%, Safe 80.9%, Danger hit 5.95%。Distillation gap (91.4%→77.7%) 主要源于固定维信息损失。

### 4.2 残差门控修复框架

#### 4.2.1 设计动机：为什么不全网络微调？

蒸馏基座网络（§4.1.3）虽然获得 77.7% success 基础性能，但仍有 5.95% danger hit 违反安全约束。自然的修复策略有两种：

**选项 A：全网络微调**  
在反例数据集上继续训练整个 π_base，最小化安全违例。

**问题**：
1. **灾难性遗忘**：反例数据集规模小（每轮数百样本）且分布偏向危险状态，微调整网络会严重损害正常状态的任务性能
2. **验证不稳定**：网络权重大幅变化导致已证明的子域失效，需重新验证
3. **冗余容量浪费**：~99% 状态下基座已经安全且高效，全网络更新浪费大部分参数容量

**选项 B：冻结基座 + 轻量门控修正头**  
保持 π_base 冻结，训练小型修正网络 δ(x)，仅在接近危险时激活干预。

**优势**：
1. **性能保护**：冻结基座保证正常状态行为不退化，77.7% success 基线不降
2. **参数效率**：修正头仅 ~22k 参数（1.7% base 大小），快速收敛且过拟合风险低
3. **验证增量性**：基座固定使已证明子域保持有效，仅需验证修正头影响的边界区域
4. **物理可解释性**：门控机制明确"何时修正"（接近威胁）与"修正幅度"（残差大小）

**min-intervention 原则**：修正网络应最小化对基座行为的干预，避免在安全状态过度修改已优化的策略。

#### 4.2.2 门控修复公式

**部署公式**：
```python
a_deploy = clip(π_base(x) + g_phys(x) · clip(δ(x), [-a_max, a_max]))
           └─────┬──────┘   └───┬────┘   └─────┬─────┘
            冻结基座        物理门控      轻量修正头
```

**三组件说明**：

1. **π_base(x)**：冻结的 MLP512 基座网络（§4.1.3），参数不更新，保持蒸馏得到的任务性能
2. **δ(x)**：轻量修正网络 44→128(ReLU)→128(ReLU)→2，~22k 参数，输出修正动作 Δa∈ℝ²
3. **g_phys(x)**：物理门控函数 g:ℝ⁴⁴→[0,1]，根据威胁距离/紧迫度自适应调节修正激活度

**物理门控设计**：

```python
g_phys(x) = mix · g_dist(x) + (1−mix) · g_ttc(x)   # mix=0.5，融合距离与时间维度

# 距离门控（径向安全裕度）
g_dist(x) = relu((d_close − min_d(x)) / (d_open − d_close))
            d_open = 3R = 0.30,  d_close = R = 0.10
            当 min_d > 0.30：g_dist ≈ 0（远离威胁，保持基座）
            当 min_d < 0.10：g_dist ≈ 1（极近威胁，全激活修正）
            中间线性过渡

# 时间紧迫度门控（碰撞倒计时）
g_ttc(x) = relu((ttc_hi − inv_ttc(x)) / (ttc_hi − ttc_lo))
           inv_ttc = close_max / max(min_d, ε)  # 逼近速度/距离 → 紧迫度
           ttc_hi, ttc_lo 为标定阈值
           高 inv_ttc（快速逼近）→ g_ttc ≈ 1
```

**门控效果**：
- **安全区**（d>0.30, inv_ttc低）：g≈0，a_deploy≈π_base，保持基座行为
- **危险区**（d<0.10, inv_ttc高）：g≈1，a_deploy≈π_base+δ，修正全激活
- **过渡区**：平滑插值，避免控制突变

#### 4.2.3 训练目标

**双损失函数**：
```python
L_total = w_ce · L_ce + w_idle · L_idle

# 反例修复损失（仅在危险样本）
L_ce = MSE(a_deploy(x_ce), a_safe(x_ce))   on x_ce ∈ CE_dataset

# 基座保持损失（在正常样本）
L_idle = MSE(a_deploy(x_normal), π_base(x_normal))   on x_normal ∈ Normal_dataset

权重：w_ce = 2.5, w_idle = 1.5
更新：仅 δ 参数，π_base 和 g_phys 固定
```

**a_safe 标签生成**（min-intervention QP）：

对于反例 x_ce（当前策略下 d2(x, π_base(x))<R），求解：
```
a_safe(x) = argmin_{a∈[-a_max,a_max]} ||a − π_base(x)||²
            s.t. d2(x, a) ≥ R + margin   # 两步安全约束 + 裕度

其中 d2(x,a) 由两步动力学展开计算（详见 §4.4）
margin = 0.02，避免边界数值不稳定
```

**设计理念**：最小化对基座的偏离（||a−π_base||²），仅在必要时修正到刚好满足安全约束的最近点，避免过度保守的修正（如直接制动）损害任务性能。

**训练配置**：
- 批大小：CE 32 + Normal 32
- 学习率：1e-4（AdamW）
- 迭代步数：每轮 600-1400 步，根据验证收敛情况提前停止
- 数据比例：CE samples 采样自验证器反例，Normal samples 从 base 安全回合采样

### 4.3 反例引导修复循环（CEGAR）

#### 迭代协议

将 §4.2 的门控修复嵌入反例引导综合（Counter-Example Guided Abstraction Refinement）循环，通过迭代"验证→收集反例→修复训练"渐进增强安全性。

**CEGAR 流程**：

```
┌─────────────────────────────────────────┐
│ 1. 采样预筛选                            │
│    在声明域 X_D 内采样 4k 状态           │
│    执行两步动力学 s' = f₂(s, π(s))     │
│    检查 d2(s, π(s)) ≥ R                 │
└────────────┬────────────────────────────┘
             ↓
          ┌──────┐   No counterexample
          │ CE?  ├─────────────────────────┐
          └───┬──┘                          ↓
              │ Yes (found violation)   ┌──────────────────┐
              ↓                         │ 5. 形式化验证     │
┌─────────────────────────────┐         │    IBP 预证明    │

│    {x_ce : d2(x_ce, π(x))<R} │         └─────────┬────────┘
└────────────┬────────────────┘                   │
             ↓                                    ↓
┌─────────────────────────────┐            ┌─────────────┐
│ 3. 生成 min-intervention    │            │ PROVEN?     │

             ↓                                 │

```

**关键设计**：

1. **采样预筛选**（步骤 1）：形式化验证器（Marabou）复杂度高（指数级），直接验证全域不可行。采样预筛选快速识别潜在危险区域，指导修复训练聚焦高风险状态。

2. **反例收集**（步骤 2）：
   - 采样反例：从预筛选发现的违例状态构造 CE_dataset
   - 验证器反例：若形式化验证失败（SAT），Marabou 返回具体反例 x_ce，加入 CE_dataset
   - 混合策略：两类反例互补，采样覆盖密集区域，验证器精准定位边界

3. **增量修复**（步骤 4）：每轮仅更新轻量修正头 δ（~22k 参数），冻结基座 π_base 和门控 g_phys，保持已验证区域稳定性

4. **收敛判据**：
   - 采样层面：4k 样本中 0 反例
   - 验证层面：IBP 或 Marabou 在声明域 X_D 返回 PROVEN
   - 实用停止：反例数量 < 阈值 或 连续轮次无显著改进

### 4.4 形式化验证协议

#### 4.4.1 两步验证的必要性

回顾 §3 动力学：p'(t+1) = p(t) + v(t)·dt，**位置不受当前动作直接影响**。动作通过双积分传播：a(t) → v(t+1) → p(t+2)。

**一步验证失效**：若仅验证 d(p(t+1))≥R，由于 p(t+1) 由旧速度 v(t) 决定，无法捕获 a(t) 的安全影响。碰撞风险要到 t+2（动作通过 v' 传播到 p''）才显现。

**两步充分性**：捕获完整因果链（动作→速度→位置）。三步及以上是同一模式的时间重复；若声明域覆盖主要危险区，可通过滚动应用两步验证覆盖更长时域。两步是 DoubleIntegrator 的**物理最小必要窗口**与**逻辑充分范围**。

#### 4.4.2 两步径向安全性质

**声明域 X_near_plus**（44 维超矩形）：

```python
X_near_plus = {x ∈ ℝ⁴⁴ |
  # Ego 状态
  v_x, v_y ∈ [-0.5, 0.5]           # 速度约束
  Δp_goal ∈ [-2, 2]²               # 目标相对位置
  Δv_goal ∈ [-1, 1]²               # 目标相对速度
  
  # 威胁距离（8 象限：4 agent + 4 obs）
  min_d_q ∈ [0.14, 0.40], ∀q∈Q0-Q7  # **近场危险区域**
  
  # 逼近速度（8 象限）
  close_max_q ∈ [-0.30, 0.30], ∀q   # **接近/远离双向**
  
  # 其他特征
  inv_ttc_q ∈ [0, 8]               # 紧迫度上界
  n_Q0_agent ∈ [1, 4]              # 强制 Q0 有邻居占用
}
```

**关键参数说明**：
- **min_d∈[0.14,0.40]**：覆盖近场危险区（1.4R 到 4R），远场 d>0.40 基座已安全
- **close∈[-0.30,0.30]**：双向逼近，包含快速接近（+0.30）和快速远离（-0.30）边界情况
- **n_Q0≥1**：确保至少一个象限有威胁占用，避免真空域（无威胁时策略平凡安全）

**两步径向安全性质 P_L2**：

定义占用感知径向距离（over-approximation）：
```python
# 仅统计有威胁占用的象限（n_q≥0.5）
d0(x) = min{min_d_q : n_q(x)≥0.5}          # 当前最近威胁距离
c0(x) = max(0, max{close_max_q : n_q(x)≥0.5})  # 最大逼近速度

# 两步动力学径向距离下界估计
d2(x, a) = d0(x) − α·c0(x) − β·||a||_∞
           α = 2·dt = 0.06    # 两步相对位移（对方速度 0.5 × 2步 × 0.03s）
           β = 0.009         # 加速度累积影响（推导自双积分器）

# 安全性质
P_L2(x) := ∀a=π(x), d2(x,a) ≥ R=0.10
```

**物理意义**：
- **d0−α·c0**：假设威胁以最大逼近速度持续两步，当前距离 d0 减去两步相对位移 2·0.5·0.03=0.06·c0
- **−β·||a||_∞**：自车加速度 a 在两步内累积改变速度，进而影响相对距离，β 系数由动力学推导
- **轴对齐盒过近似**：实际相对速度向量，用 ||·||_∞ 上界估计最坏情况

**Soundness 保证**：

d2(x,a)≥R 是**充分条件**（over-approximation）：
```
d2(x,a)≥R  ⟹  真实两步后最小平面距离 d_plane(t+2)≥R
```
但反向不成立（存在 d_plane≥R 但 d2<R 的情况，因为过近似保守）。

**完备性权衡**：过近似导致部分安全状态被误判为"未证明"，但保证已证明状态绝对安全（zero false positives）。

#### 4.4.3 验证方法

**两阶段验证策略**：

**阶段 1：IBP 快速预证明**

区间界传播（Interval Bound Propagation）逐层计算网络输出界：
```python
[a_lo, a_hi] = IBP(π, X_near_plus)  # 在整个输入盒上传播

d2_lo = d0_lo − α·c0_hi − β·max(|a_lo|, |a_hi|)  # 下界估计

if d2_lo ≥ R:
    return PROVEN  # 整盒证明，耗时 ~2ms
else:
    return UNKNOWN → 进入阶段 2
```

**阶段 2：Marabou 完备验证 + 自适应切分**

当 IBP 报告 UNKNOWN，沿关键维度（min_d, close_max）递归切分：
```python
def verify_box(X, depth):
    if IBP(π, X).d2_lo ≥ R:
        return PROVEN
    
    if X.width ≤ threshold (0.08):  # 小盒停止切分
        result = Marabou(π, X, timeout=25s)  # SMT 求解
        if result == UNSAT:
            return PROVEN
        elif result == SAT:
            return COUNTEREXAMPLE(result.witness)
        else:
            return TIMEOUT
    
    # 递归切分沿 min_d 或 close_max
    X_left, X_right = split(X, dim=select_critical_dim())
    return verify_box(X_left) AND verify_box(X_right)
```

**Marabou 编码**（SMT 约束）：
```smt
; 输入域约束
(assert (and (>= x[0] 0.14) (<= x[0] 0.40) ...))

; 网络前向传播（ReLU 分支）
(assert (= h1[i] (ite (>= z1[i] 0) z1[i] 0)))  ; ReLU 层

; 两步动力学展开
(assert (= d2 (- (- d0 (* 0.06 c0)) (* 0.009 (abs a)))))

; 违例查询（寻找反例）
(assert (< d2 0.10))

; 求解
(check-sat)  ; UNSAT→proven, SAT→counterexample
```

**验证结果（r2 主验收）**：

| 项 | 值 | 说明 |
|---|---|------|
| **状态** | **PROVEN_FULL** | 整盒 IBP 证明 |
| 声明域 | d∈[0.14,0.40], \|c\|≤0.30 | 44-D 超矩形 X_near_plus |
| 性质 | d2(x,π(x)) ≥ 0.10 | 两步径向 L2 安全 |
| **d2_lo（IBP）** | **0.113** | ≥ R=0.10 ✓，裕度 0.013 |
| 验证时间 | ~2ms | IBP 单次查询 |
| 交叉验证 | 0 反例 / 4k 采样 | 采样一致性确认 |

**关键成就**：无需切分即完成整域证明，验证器输出下界 d2_lo=0.113 超过安全阈值 R=0.10，在声明域内任意状态 x∈X_near_plus 满足 ∀a=π(x), d2(x,a)≥0.10。

## 6. 局限与未来工作

### 已证明 vs 未证明

**✅ 已证明**：
- L2 near_plus 盒（d∈[0.14,0.40], |c|≤0.30）两步径向安全
- 完备 ∀ 证明（IBP + Marabou）
- 79.6% 经验危险覆盖

**❌ 未证明**：
- 无限时域全局安全（非前向不变；20.4% 未覆盖）
- 平面几何完备性（径向过近似可能虚警）
- 网络依赖带（mid-F d∈[0.125,0.14) 仍开放）

### 动力学设计影响

**当前选择**：两步验证源于 DoubleIntegrator 控制延迟（动作影响加速度 → 速度 → 位置，见 §3.1 式 1-2），位置不受当前动作直接影响，必须前瞻两步。

**理论可能性**：单积分器（速度控制 p'=p+v_cmd·dt）可降为一步验证，且 c' 直接可控，理论上更容易证明前向不变性，**完全验证**（全状态空间）在理论上更可行。

**但仍面临挑战**：
1. **即使一步验证，全量通过仍困难**：如 §5.6 所示，扩大范围后反例数量指数增长（L3 有 11260 个反例），CEGAR 修复成本与性能 tradeoff 加剧。完全验证的理论可行性不等于全量通过的实践可达性。
2. **物理不可实现**：单积分器假设速度瞬时改变，违反惯性定律。实际系统中执行延迟（控制周期、传感器延迟、执行器响应）不可避免，单步最大 Δv≈0.3 m/s，大幅转向需 3-4 步。
3. **工程真实性**：我们选择 DoubleIntegrator 保证动力学真实性，代价是需要两步验证和更大的证明难度。

**未来方向**：分层验证（外环 MF + 内环低层跟踪器）可桥接理论与实践；或与动力学协同设计（延迟补偿控制）以缩小验证步数。

### 其他局限与方向

1. **全局安全**：前向不变集搜索；分层 RTA（运行时保证，MF+HandCBF 切换）；滚动时域验证
2. **更紧性质**：椭圆包络替代径向 L2（消除过近似虚警）；平面几何约束
3. **可扩展性**：N>8（层次聚合，避免象限饱和）；3D（八分体聚合）；异构智能体（类型条件聚合）
4. **训练效率**：在线 CEGAR（边训练边验证）；修复代价敏感采样；多域联合优化

## 7. 结论

本文提出**首个在实际多智能体强化学习任务上达成完备形式化安全证明的控制器**。三项技术创新使这一突破成为可能：① 44 维固定维平均场架构桥接 GNN 与验证器（接受性能权衡以获得可验证性）；② 残差门控 CEGAR 修复保持协调能力同时修复违例（危险碰撞率降低 12.7×）；③ 有界完备形式化证明（L2 声明域 PROVEN_FULL，覆盖 79.6% 经验危险状态）。

**实验验证**（8 智能体 DoubleIntegrator，N=8, L=40m）：MF-r2 达成 82.0% success、96.5% safe、0.31 cost、1.37ms latency。对比六个基线（GCBF+、DeepSet-r2、HandCBF、MAPPO-Lag、InforMARL、coast-base），部分方法展现更高任务性能（GCBF+ 91.4%），但**均无完备形式化证书**——核心贡献是**证书非对称性**（certificate asymmetry），而非单纯经验性能优势。

**理论贡献**：证明了固定维聚合的可验证 MARL 存在性。即使性能略低于变长 GNN（82.0% vs 91.4%），完备证书的不可替代价值使权衡可接受。本工作确立**实际 MARL 形式化验证的可行性**，为安全关键部署（UAV 集群、自动驾驶车队、手术机器人）开辟道路。

**诚实边界**：证明范围为 L2 声明域内的两步径向 L2 性质（动作 → 加速度 → 速度 → 位置的双积分延迟），非无限时域全局安全或前向不变集。20.4% 经验危险状态位于声明域外（L3 扩展域有 11260 反例），完全验证理论可行但全量通过面临实践挑战（§6.2）。

**未来工作**：前向不变集搜索、分层验证（外环 MF + 内环跟踪器）、动力学协同设计（缩小验证步数）、更紧性质（椭圆包络）、可扩展性（N>8、3D、异构）。

**验证不再是遥不可及——它是可实现的。** 我们邀请社区探索多智能体系统"性能-安全-可验证性" Pareto 前沿。
